# Guided Accounts pane

User reports that the terminal pane is incomprehensible. Replace its developer
control form with two clickable views: Accounts and Conversations. Account rows
show names/login state and have Log in, Check login and Add account actions.
Accept a friendly account name and derive its internal slug in Python. Start a
conversation only when requested, using a selected project or a folder field.
Show owned conversations as selectable rows. Existing shared conversations get
one named Switch to account button; hide irrelevant setup fields.

Switch setup uses explicit account checkboxes in click order. Compatibility
verification and sharing each get a dedicated confirmation view explaining
allowance/context access. Preserve all existing backend proof, stopped-source,
identity, transition and writer guards. No model calls on render/list refresh.
Legacy snapshot handoff remains CLI-only. No automatic capability grants or
native prompt acceptance. Native SSO stays in the program surface with a visible
Done/back button.

Lua VM has no JSON parser; use a bounded percent-encoded TSV read model generated
by the Python adapter and friendly operation summaries, rather than JSON regexes.
Only the account-specific display transport changes; Accounts/Shared remain the
policy owners. Clickable buttons/fields and keyboard Tab/Enter are primary;
remove the Alt shortcut wall. Preserve F7 toggle and the Accounts action-band pill.
Show clear permission instructions and an Open Settings button while untrusted.

Validate backend name/transport edges and no side effects on refresh, render and
click handlers with stubbed Lua if available, real plugin check and isolated TUI
focus/navigation. Install on this connected Mac, push changes; the photographed
Windows/WSL installation must be updated there separately. Never claim it was
updated remotely or certify Enterprise auth from synthetic tests.
